# SPEC-019. Команда `/help`

**Проект:** Telegram-бот «PostMaster»
**Этап:** MVP
**Версия:** 1.0
**Статус:** реализовано

## 1. Назначение

`/help` показывает короткую пользовательскую инструкцию и доступна из любого шага сценария. Команда не обращается к БД, не меняет FSM и не очищает временные данные.

## 2. Scope и зависимости

Справка описывает базовый сценарий создания публикации, актуальный формат даты и пример, `/start`, `/my_posts`, `/cancel <post_id>`, `/help`, режим напоминания и автоматическую публикацию в Telegram-канал. Используются существующие функции SPEC-002, 004–005, 014–018.

## 3. Текст справки

```text
PostMaster помогает запланировать публикацию фотографии.

Как создать публикацию:
1. Отправьте фотографию; если нужна подпись, добавьте текст к фото в Telegram.
2. Укажите дату и время в формате ДД.ММ.ГГГГ ЧЧ:ММ.
3. Дождитесь подтверждения.

Пример даты: 07.10.2026 15:00

В режиме напоминания бот пришлёт вам фотографию и напоминание.
В режиме Telegram бот опубликует фотографию в указанном Telegram-канале.

Команды:
/start — начать работу
/my_posts — показать запланированные публикации
/cancel <post_id> — отменить публикацию, например /cancel 42
/help — показать эту справку
```

## 4. Поведение и ошибки

Handler только отправляет константный справочный текст. Команда работает в личном чате при любом состоянии (`IDLE`, `WAITING_PHOTO`, `WAITING_DATETIME`) и не вызывает сервис диалога. При ошибке `send_message` логируется `Help message send failed` с Telegram ID и типом исключения; FSM остаётся нетронутой.

## 5. Acceptance Criteria

- **AC-019-01:** `/help` отправляет справку.
- **AC-019-02:** перечислены `/start`, `/my_posts`, `/cancel`, `/help`.
- **AC-019-03…04:** присутствуют шаблон даты и пример.
- **AC-019-05…07:** команда срабатывает в `IDLE`, `WAITING_PHOTO`, `WAITING_DATETIME`.
- **AC-019-08…09:** FSM-состояние и черновик остаются прежними.
- **AC-019-10:** не создаются Post и Scheduler job, не изменяется БД.
- Send failure логируется, без текста исключения в журнале.

## 6. Тестирование и инварианты

Проверяются состав справки, интеграция с Telegram, доступность в каждом состоянии, сохранение `telegram_file_id`, отсутствие изменений БД и Scheduler, продолжение создания публикации после `/help`, а также логирование ошибки отправки.

Инварианты: справка не меняет бизнес-состояние и FSM; не удаляет данные черновика; не создаёт Post; описывает только доступные функции.
