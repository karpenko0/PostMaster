# SPEC-002. Пользователь и команда /start

Проект: Telegram-бот «PostMaster»
Этап: MVP
Статус: проектная спецификация

## 1. Цель

Регистрировать Telegram-пользователя и запускать основной сценарий через `/start`.

## 2. Scope

- создание/получение пользователя по `telegram_user_id`
- команда `/start`
- приветствие
- переход в `WAITING_PHOTO`

## 3. User Stories

- **US-01.** Как новый пользователь, я хочу запустить `/start`, чтобы начать планирование публикации.
- **US-02.** Как вернувшийся пользователь, я хочу снова выполнить `/start`, чтобы начать новый сценарий без создания дубликата профиля.

## 4. Бизнес-правила

- **BR-01.** `telegram_user_id` уникален.
- **BR-02.** При повторном `/start` новый пользователь в БД не создаётся.
- **BR-03.** После `/start` состояние пользователя — `WAITING_PHOTO`.
- **BR-04.** Если timezone не задана пользователем, используется `DEFAULT_TIMEZONE`.

## 5. API / интерфейсные контракты

Telegram Bot API

**Вход:** команда `/start`.

**Выход:** приветствие и просьба отправить фотографию.

Внутренний сервис

```
UserService.get_or_create(telegram_user_id, username, first_name) -> User
```

## 6. Данные и таблицы БД

Используется таблица `users`:

| Поле | Тип | Ограничения/назначение |
|---|---|---|
| `id` | INTEGER | Внутренний идентификатор |
| `telegram_user_id` | BIGINT | Telegram ID, UNIQUE |
| `username` | VARCHAR | Username пользователя |
| `first_name` | VARCHAR | Имя пользователя |
| `timezone` | VARCHAR | Часовой пояс пользователя |
| `created_at` | DATETIME | Дата создания |
| `updated_at` | DATETIME | Дата изменения |

## 7. Основной сценарий

1. Система получает входные данные, относящиеся к данной спецификации.
2. Выполняются бизнес-правила и проверки этой SPEC.
3. При успешном результате состояние/данные изменяются согласно указанным контрактам.
4. При ошибке операция не должна нарушать ранее сохранённые данные; применяется предусмотренная этой SPEC обработка.

## 8. Критерии приёмки

- **AC-01.** Новый пользователь создаётся один раз.
- **AC-02.** Повторный `/start` не создаёт дубликат.
- **AC-03.** Бот отвечает приветствием.
- **AC-04.** После ответа ожидается фотография.

## 9. Тестирование

- **TC-01.** Новый пользователь.
- **TC-02.** Повторный `/start`.
- **TC-03.** Пользователь без username.
- **TC-04.** Проверка уникальности `telegram_user_id`.

## 10. Ограничения

- Реализуются только требования, перечисленные в этой спецификации и исходном техническом задании PostMaster.
- Неописанные функции, поля, роли, интеграции и пользовательские сценарии не входят в scope данной SPEC.
