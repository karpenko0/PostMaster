# SPEC-003. FSM и управление состоянием диалога

Проект: Telegram-бот «PostMaster»
Этап: MVP
Статус: проектная спецификация

## 1. Цель

Управлять состояниями диалога пользователя в рамках сценария создания публикации.

## 2. Scope

- состояния `IDLE`, `WAITING_PHOTO`, `WAITING_DATETIME`
- переходы между состояниями
- обработка новой фотографии в `WAITING_DATETIME`

## 3. User Stories

- **US-01.** Как пользователь, я хочу, чтобы бот понимал, на каком шаге создания публикации я нахожусь.

## 4. Бизнес-правила

- **BR-01.** `/start` переводит в `WAITING_PHOTO`.
- **BR-02.** Фото переводит в `WAITING_DATETIME`.
- **BR-03.** Корректная дата и создание поста возвращают в `IDLE`.
- **BR-04.** При новой фотографии в `WAITING_DATETIME` допускается замена предыдущего фото и повторный запрос даты.

## 5. API / интерфейсные контракты

FSM-контракт

```
/start -> WAITING_PHOTO
PHOTO -> WAITING_DATETIME
VALID_DATETIME -> IDLE
```

## 6. Данные и таблицы БД

Новые постоянные таблицы не требуются. Данные готовящейся публикации могут существовать как состояние диалога до создания записи `posts`.

## 7. Основной сценарий

1. Система получает входные данные, относящиеся к данной спецификации.
2. Выполняются бизнес-правила и проверки этой SPEC.
3. При успешном результате состояние/данные изменяются согласно указанным контрактам.
4. При ошибке операция не должна нарушать ранее сохранённые данные; применяется предусмотренная этой SPEC обработка.

## 8. Критерии приёмки

- **AC-01.** Все три состояния реализованы.
- **AC-02.** Переходы выполняются только согласно утверждённому сценарию.
- **AC-03.** После успешного создания поста состояние `IDLE`.
- **AC-04.** Новая фотография на шаге даты корректно обрабатывается.

## 9. Тестирование

- **TC-01.** Проверка каждого перехода.
- **TC-02.** Недопустимое сообщение в каждом состоянии.
- **TC-03.** Повторная фотография в `WAITING_DATETIME`.

## 10. Ограничения

- Реализуются только требования, перечисленные в этой спецификации и исходном техническом задании PostMaster.
- Неописанные функции, поля, роли, интеграции и пользовательские сценарии не входят в scope данной SPEC.
